# briefing — reference

Schema, index format, lifecycle semantics, and per-subcommand procedures for
`pickup`, `done`, `release`. SKILL.md covers `request` inline (the most-common
case); this file is loaded on-demand when SKILL.md cites it during a
subcommand other than `request`.

## Schema — YAML frontmatter (all briefings)

Every briefing file under `briefings/<NNN>-<slug>.md` carries this exact
frontmatter at the top, then the H1 `# Briefing: <title>`, then the body
sections. The frontmatter is the source of truth — indexer, boot digest, and
slash commands all read it.

```yaml
---
title: "<short title>"            # required string
date: "YYYY-MM-DD"                # required ISO date
author: "<one-line blurb>"        # required string (single line preferred)
status: open                      # open | delivered | archived
claimed_by_session: null          # null | URL of claiming session
claimed_at: null                  # null | YYYY-MM-DD when claimed
delivered_at: null                # null | "YYYY-MM-DD via <PR/issue ref>"
---
```

Status enum:

- **open** — filed; awaiting pickup or in-flight. The `claimed_by_session`
  field distinguishes the two: null = awaiting pickup; URL = in flight.
- **delivered** — the target work the briefing oriented landed.
- **archived** — the framing has drifted from current practice. Preserved
  under `_archive/<date>_<slug>/` per `operations/draft_lifecycle.md` section 2.

The boot digest surfaces only the strictly "needs pickup" subset:
`status == "open" AND claimed_by_session == null`. Claimed briefings are
already being worked and don't need recall.

## Index — briefings/briefing_index.json

Flat JSON array, sorted ascending by `nnn`, one entry per file. Generated by
`bin/briefings-index.py --write`; gated by the `Briefings index` CI workflow.

```json
[
  {
    "nnn": 37,
    "slug": "skills-design-overhaul",
    "title": "Skills design overhaul — fix the systemic auto-trigger failure",
    "date": "2026-05-26",
    "author": "...",
    "status": "open",
    "claimed_by_session": null,
    "claimed_at": null,
    "delivered_at": null,
    "file_path": "briefings/037-skills-design-overhaul.md"
  },
  ...
]
```

Useful jq slices:

```bash
# Briefings needing pickup
jq '[.[] | select(.status == "open" and .claimed_by_session == null)] | sort_by(.nnn)' \
  briefings/briefing_index.json

# Currently claimed (in-flight)
jq '[.[] | select(.status == "open" and .claimed_by_session != null)]' \
  briefings/briefing_index.json

# Delivered recently
jq '[.[] | select(.status == "delivered")] | sort_by(.delivered_at) | reverse | .[0:10]' \
  briefings/briefing_index.json
```

## Shared mechanics

All three subcommands below share three building blocks. Inline them rather
than restate them in every section.

**Locate the file** (NNN is the briefing number, may be 1-3 digits at the CLI):

```bash
NNN="$(printf '%03d' "$1")"
FILE="$(ls "$COO/briefings/${NNN}-"*.md 2>/dev/null | head -1)"
[ -n "$FILE" ] || { echo "briefing: no file for ${NNN}"; exit 1; }
```

**Mutate frontmatter** via the bundled script — atomic, only touches the
declared keys, leaves the body untouched:

```bash
python3 "${CLAUDE_SKILL_DIR:-.claude/skills/briefing}/scripts/update-frontmatter.py" \
  "$FILE" --set key=value [--set key=value ...]
```

The script accepts `null`, `true`, `false`, and bare strings. Whitespace or
special chars get quoted automatically. See the script's `--help` for the
full grammar.

**Commit + push + PR** (same shape for all three; the title and `--set`
values are what differ):

```bash
cd "$COO"
python3 bin/briefings-index.py --write
git checkout -b "claude/briefing-${NNN}-<verb>"
git add briefings/ && git commit -m "Briefing ${NNN}: <verb> message"
git push -u origin HEAD
bash "${VADE_RUNTIME_DIR:-/home/user/coo-harness}/scripts/gh-pr-create.sh" \
  --repo coo-labs/coo-memory --base main --head "$(git branch --show-current)" \
  --title "Briefing ${NNN}: <verb>" \
  --body "<short body>"
```

## pickup — claim an open briefing

`/briefing pickup` (no argument):

1. Read the index and surface open-and-unclaimed briefings to the user:
   ```bash
   jq -r '[.[] | select(.status == "open" and .claimed_by_session == null)]
          | sort_by(.nnn) | .[]
          | "  " + (.nnn | tostring) + " " + .slug + " — " + .title' \
     "$COO/briefings/briefing_index.json"
   ```
2. Ask which NNN to claim. When the user answers, re-invoke as
   `/briefing pickup <NNN>`.

`/briefing pickup <NNN>`:

1. Locate the file (Shared mechanics). If the briefing is already claimed,
   fail with a clear message; tell the user to `release` it first if they
   meant to take it over.
2. Get the session URL:
   ```bash
   SESSION_URL="$(bash "${VADE_RUNTIME_DIR:-/home/user/coo-harness}/scripts/coo-session-url.sh" 2>/dev/null \
     || echo "run-$(date -u +%Y-%m-%dT%H%M%S)")"
   ```
3. Mutate frontmatter:
   ```bash
   python3 "${CLAUDE_SKILL_DIR:-.claude/skills/briefing}/scripts/update-frontmatter.py" \
     "$FILE" \
     --set claimed_by_session="$SESSION_URL" \
     --set claimed_at="$(date -u +%Y-%m-%d)"
   ```
4. Commit + push + PR (branch: `claude/briefing-${NNN}-pickup`, title
   `Briefing ${NNN}: claim`). Body names the session URL and explains that
   status stays `open` until `/briefing done`.

## done — mark delivered

`/briefing done <NNN> [--via <PR or issue ref>]`:

1. Locate the file.
2. Mutate frontmatter (claim fields nulled because delivery supersedes them):
   ```bash
   DELIVERED_AT="$(date -u +%Y-%m-%d)${VIA:+ via $VIA}"
   python3 "${CLAUDE_SKILL_DIR:-.claude/skills/briefing}/scripts/update-frontmatter.py" \
     "$FILE" \
     --set status=delivered \
     --set delivered_at="$DELIVERED_AT" \
     --set claimed_by_session=null \
     --set claimed_at=null
   ```
3. Commit + push + PR (branch: `claude/briefing-${NNN}-done`, title
   `Briefing ${NNN}: delivered`).

If the user runs `/briefing done <NNN>` from the same branch where the
target work landed, fold the frontmatter update into that branch's existing
PR instead of opening a new one — one less PR to review.

## release — clear a claim without delivering

`/briefing release <NNN>`:

1. Locate the file.
2. Mutate frontmatter (status stays `open` — the briefing returns to the
   pool):
   ```bash
   python3 "${CLAUDE_SKILL_DIR:-.claude/skills/briefing}/scripts/update-frontmatter.py" \
     "$FILE" \
     --set claimed_by_session=null \
     --set claimed_at=null
   ```
3. Commit + push + PR (branch: `claude/briefing-${NNN}-release`).

Use when a session that claimed a briefing can't finish it (out-of-scope,
blocked, abandoned). Another session can then `pickup` it cleanly.

## Lifecycle summary

| Event | Subcommand | What changes |
|---|---|---|
| Author writes the framing | `/briefing request` | New file, `status: open`, claim null |
| Recipient session starts work | `/briefing pickup NNN` | `claimed_by_session` + `claimed_at` set |
| Target work merges | `/briefing done NNN [--via REF]` | `status: delivered`, `delivered_at` set, claim nulled |
| Recipient can't finish | `/briefing release NNN` | Claim nulled; status stays open |
| Framing obsolete | (manual) | Move to `_archive/`, set `status: archived` |

## Failure modes

- **Two sessions both run `pickup NNN`** at the same time — second write wins
  on disk, but the loser will see merge conflict on push. SKILL.md applies
  the same collision-tolerance pattern to `request`. Resolve by picking one
  of the two claims and re-running `release` on the other.
- **Session URL unavailable** (`coo-session-url.sh` not on PATH or fails) —
  the dispatch helper falls back to `run-<UTC timestamp>` so pickup never
  fails outright.
- **Frontmatter parse error during update** — exit non-zero; do not write a
  half-corrupted file. User must inspect and fix the frontmatter manually.
